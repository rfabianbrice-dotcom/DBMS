## About the project

A relational database that helps a university campus measure its **Environmental, Social and Governance (ESG)** performance. Assessors visit campus facilities (academic blocks, hostels, laboratories, library, cafeteria and so on) once per academic year and record measured values for ESG indicators such as electricity consumption, waste recycling rate or accessibility compliance. Each value is compared with a target to decide whether the facility is compliant. The campus also tracks sustainability initiatives (for example rooftop solar) with budgets and statuses.

All assignments use this single project and one finalized 3NF database design.

## Database design

Database name: `campus_esg_db` (MySQL 8.0.16 or later, InnoDB, `utf8mb4`).

| Table | Purpose |
|---|---|
| `department` | Academic and administrative departments |
| `esg_category` | The three ESG pillars: Environmental, Social, Governance |
| `facility` | Buildings and spaces that are assessed |
| `esg_indicator` | Measurable indicators with unit, target and preferred direction (higher or lower is better) |
| `assessor` | Staff who carry out assessments |
| `assessment` | One yearly assessment of one facility by one assessor |
| `assessment_result` | Measured value of one indicator within one assessment |
| `sustainability_initiative` | Projects with budget, dates and status |

**Relationships (all one-to-many):** department → facility, department → assessor, esg_category → esg_indicator, esg_category → sustainability_initiative, facility → assessment, facility → sustainability_initiative, assessor → assessment, assessment → assessment_result, esg_indicator → assessment_result.

**Constraints:** 8 primary keys, 9 foreign keys, 7 UNIQUE, 13 CHECK and 6 DEFAULT constraints. The ER diagram is in Assignment 3 (Figure 1) and Assignment 5.

**Sample data (Assignment 7):** 147 rows in total (8 departments, 13 facilities, 13 indicators, 19 assessments, 71 results, 14 initiatives and so on) covering academic years 2024-25, 2025-26 and 2026-27. All people and figures are fictional; e-mail addresses use the reserved `.example` domain.

## Running the SQL 

1. Install **MySQL 8.0.16 or later** (earlier versions ignore `CHECK` constraints).
2. Run the statements from the assignments in this order:
   1. Assignment 5: `CREATE DATABASE` and the eight `CREATE TABLE` statements
   2. Assignment 7: the `INSERT` statements (already in foreign-key order)
   3. Assignments 8 and 9: the queries
   4. Assignment 6 (optional): the constraint tests; run these on a scratch database because they modify data
3. Use MySQL Workbench or the `mysql` client and take screenshots of the results if your submission requires them.

## Regenerating the documents 

The Word files are generated by Python scripts in `generator_scripts/`.

**Requirements:** Python 3.10+, `python-docx` and Pillow (`pip install python-docx pillow`), and [Graphviz](https://graphviz.org/) (the `dot` command) for the ER diagram.

```bash
cd generator_scripts
python build.py        # writes the seven .docx files into ./out
```

| Script | Role |

| `common.py` | python-docx helpers: header, headings, shaded code blocks, tables, footer |

| `build.py` | Builds all seven documents |
